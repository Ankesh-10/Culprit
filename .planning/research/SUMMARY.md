# Project Research Summary

## Key Findings

- **Recommended stack:** Use Node 22 LTS with an exact patch pinned in `.nvmrc`, npm with a committed `package-lock.json`, Vite, strict TypeScript, and Vitest. Keep the application dependency-light: native DOM/CSS, browser Web Workers, and hand-authored SVG are sufficient. Ship local fonts and fixtures; use no runtime network, AI, server, database, charting library, UI framework, date library, or parser generator unless a measured requirement later proves one necessary.
- **Core boundary:** Put a serializable, pure TypeScript analysis pipeline in `src/core`, isolated from DOM, filesystem, locale, current time, randomness, and network concerns. A thin Vite UI orchestrates inputs and presentation; a worker adapts the same `analyze` function for larger inputs. Use stable contracts, UTC-normalized timestamps, explicit collection ordering, typed errors, and canonical serialization.
- **Table stakes:** The credible MVP is one complete path from JSON-lines or documented plain-text logs plus one documented git-history export through parsing, normalization, signature grouping, onset/error-rate detection, explainable ranking, and a top-three verdict. It must include the three bundled incidents, evidence-linked suspect details, an accessible timeline, Markdown postmortem copy, provenance/UTC disclosure, and intentional empty, loading, validation-error, no-incident, low-confidence, responsive, and accessible states.
- **Trust model:** Scores are ranked suspicion, not causal proof or probability. Freeze and version weights for proximity, trace/file match, novelty, and bounded churn; retain each feature contribution and evidence reference; define deterministic tie-breakers; and make low confidence explicit when onset, evidence, history, or score separation is weak. “No clear culprit” is a valid result.
- **Architecture/build order:** Establish contracts, fixtures, canonical output, pinned tooling, Docker, README, and the offline test command first. Then implement logs and errors, signatures/buckets, onset detection, history parsing, scoring/confidence, the worker, a minimum console around one fixture, and finally all fixtures, inputs, timeline interactions, copy, accessibility, responsive behavior, and release checks. This order exposes parsing and algorithm risk before visual polish while still producing an early vertical slice.
- **Highest-risk pitfalls:** Silent malformed-input loss and broken multiline stacks; mixed timezone/precision handling; noisy or gradual onset misclassification; false causal language; path and line-range mismatches across platforms; generic/vendor frames or large commits overpowering relevant evidence; opaque or unstable scores; polished UI hiding truncation and uncertainty; page freezes or oversized SVG DOMs; inaccessible hover-only timelines; unrealistic or drifting fixtures; and a Docker/README rebuild that only works on the author’s machine.

## Implications for Roadmap

Build the first milestone as a coarse-grained vertical MVP with each checkpoint demonstrably usable:

1. **Foundation and rebuild surface:** Pin Node 22, create the Vite/TypeScript/Vitest project, commit the lockfile, add Docker, `.env.example`, README setup/run/test/deploy instructions, the single offline `make test` command, canonical serialization, and one shared fixture manifest. Make all paths repository-relative and all tests independent of local time, locale, network, and machine paths.
2. **Analysis slice:** Define the input/result/error contracts, then implement strict JSONL and plain-text parsing with bounded input, line-aware diagnostics, multiline stack handling, UTC normalization, stable IDs, conservative error signatures, and fixed UTC buckets. Add tests for malformed records, offsets, ties, gaps, spike/ramp/no-incident/insufficient-data outcomes, and deterministic repeated output.
3. **Evidence and verdict:** Implement the narrow self-describing history export with commits, touched files, and changed line ranges. Canonicalize repository-relative paths, distinguish exact/nearby/file-only/no matches, exclude or downweight vendor/generated frames, score only eligible pre-onset commits with frozen `SCORING_V1` weights, and return per-signal explanations, evidence references, stable top-three ordering, and qualitative confidence. Contract-test checkout, slow-burn, and ambiguous fixtures for intended reasoning rather than only a winner.
4. **Thin console:** Wire the same core and fixtures into a browser worker and render the verdict card, top-three shortlist, score/evidence breakdown, error groups, selected suspect detail, and a basic accessible timeline connecting rates, onset, commits, and source lines. Add one-click fixture loading, file/text input, recoverable states, explicit privacy/UTC/limitations copy, and deterministic Markdown postmortem copy. Ensure keyboard and non-hover users can reach equivalent timeline information.
5. **Hardening:** Profile near the documented cap, use worker execution and bounded rendering where necessary, verify responsive layouts and visible focus at narrow widths/zoom, audit contrast and status semantics, test clean Linux/Docker rebuilds, and rehearse all three demo incidents. Preserve analysis warnings and assumptions as first-class UI and export metadata.

**Explicitly defer:** live streaming; runtime AI/ML; accounts, databases, cloud storage, telemetry, uploads, and integrations; whole-repository browser upload; auto-fix/rollback/deploy actions; configurable weights; a CLI helper; additional log/history formats; side-by-side suspect comparison; standalone report/PDF export; historical persistence or repeated-run baselines; themes, localization, print styling, and elaborate density modes; fancy graph visualization; chart/UI/state/date/parser dependencies; and advanced filtering or cancellation/progress work unless profiling or usability demonstrates a need. If time is constrained, cut animation, deep filtering, full diff rendering, arbitrary text history, and framework abstractions before cutting deterministic serialization, clear errors, multiline parsing, onset evidence, low-confidence handling, accessible timeline fallback, or fixture contract tests.
