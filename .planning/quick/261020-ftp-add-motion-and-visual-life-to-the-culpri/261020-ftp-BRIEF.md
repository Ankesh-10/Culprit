## What to build (priority order; cut from the bottom if budget is tight, never cut the safety rules)

1. **Entrance choreography.** Result sections (status banner, verdict, lineup, timeline, log panel, signatures, trust footer) fade and rise: `translateY(12px)` + `opacity 0` resolving over 600ms `cubic-bezier(0.16,1,0.3,1)`, staggered ~80ms by index (CSS custom property `--index`). One shot per render of a result. Use CSS animation classes toggled by the renderer; `IntersectionObserver` only for sections below the fold (guard `typeof IntersectionObserver`).
2. **Timeline life.** On a new result: the error line draws in (stroke-dashoffset), the onset band wipes in (scaleX from its left edge, transform-origin), commit diamonds pop in staggered (scale), a one-shot pulse ring on the #1 suspect marker (scale + opacity, plays once, not looping), readout bar text swaps with a quick 150ms fade. Re-selecting a bucket or filtering must NOT replay the draw-in (only the first render of a result); filter changes may crossfade the series.
3. **Verdict reveal.** The 7-char short hash decodes character by character (about 450ms total) and ENDS on the exact hash; the DOM text must be the exact final hash from the first paint for assistive tech and tests (e.g. keep real text in the element, animate an overlay or use `aria-label`/visually hidden copy, or apply the decode via a pseudo/overlay span that is `aria-hidden`). Matching-error count and score count up (about 600ms), final values exact; score and confidence meters fill (transform scaleX). Never leave a wrong value visible after the animation or if JS animation is skipped.
4. **Case cards and loading.** Hover and focus-visible: border brightens (hairline-strong) and the sparkline draws in (stroke-dashoffset). The loaded card keeps its quiet indicator. The analyzing state shows a thin scanline sweep (transform translateX on a flat 2px bar at low opacity) over a text-only placeholder (no skeleton shapes, per UI-SPEC).
5. **Drawer.** The suspect drawer slides in from the right (transform) with a backdrop fade (opacity). On phones it slides up or in from the right; closing may be instant (native dialog close is synchronous: do not delay focus return).
6. **Raycast signature moment.** A flat diagonal stripe band behind the header, ONCE per page: three flat diagonal stripes (red family `#ff5757`, `#e04848`, `#a1131a`) at different low opacities (<= 0.5), NO gradients (flat fills only, e.g. an inline SVG with three skewed rects or `transform: skewX`), clipped to the header height, `aria-hidden`, `pointer-events: none`, must not reduce text contrast (verify text over it stays >= 4.5:1 by keeping stripes behind a flat header region or low opacity and re-computing). Red is decoration only here.
7. **Ambient layer (optional).** A fixed, `pointer-events: none`, `aria-hidden` flat dot-grid or soft flat shapes layer at <= 0.04 opacity with one very slow (>= 40s) transform drift. Flat colors only. Skip if it risks contrast, perf or the design-rules test.
8. **Command palette.** `/` (when focus is not in an input/textarea/select/contenteditable) and Ctrl/Cmd+K open a small native `<dialog>` palette: a search box filtering the three bundled cases (and "Use your own files"), `kbd` hints, ArrowUp/ArrowDown to move, Enter to load, Esc to close, focus returns to the opener. It supplements the existing controls; every existing control stays reachable without it. Use `role="listbox"`/`option` or an equivalent accessible pattern; announce results count politely. Add a visible, discoverable hint in the UI ("Press / to jump to a case" with `kbd`), but keep the existing timeline key hint.

## HARD RULES

- Motion only via `transform`, `opacity` and SVG `stroke-dashoffset`. No layout-shifting animation (no animating width/height/top/left/margin).
- Every animation and transition is inside `@media (prefers-reduced-motion: no-preference)`; under `prefers-reduced-motion: reduce` content is at its final state instantly (counts exact, hash exact, meters full, line fully drawn). The base (no media query, no JS) state must already be the correct final state: motion is an enhancement that animates FROM an initial state set inside the no-preference media query or by a class added by JS, so a JS failure never hides content.
- No timers or animation may block input, delay focus handling, or run after unmount in a way that throws. Cancel pending animations when a new result renders (latest-request-wins stays intact).
- No gradients, no box-shadow, no glass, no backdrop-filter, no looping attention-seeking animation (the pulse ring plays once; the ambient drift is the only loop and is gated).
- Keep every existing DOM id/aria contract, focus behavior and all copy under `tests/ui/*`. Update tests rather than weakening them: the static design-rules test in `tests/ui/contrast.test.ts` or wherever the "Raycast design rules" test lives currently bans transitions/animations/gradients; relax ONLY to allow transitions/animations/keyframes that are inside a `prefers-reduced-motion: no-preference` block and animate only transform/opacity/stroke-dashoffset, and (for item 6) flat stripes without `gradient(`. It must still fail on gradients, shadows, glass, ungated motion and properties outside that list. Add tests for the pure parts (decode/count-up frame functions, palette filtering/keyboard model, stagger index) as DOM-free Vitest.
- No network, no new dependencies, do not touch `src/core/`. `src/ui/*` and `src/styles.css` and `index.html` are in scope.
- Static safety test stays green (no innerHTML, no fetch/network APIs, no timers that read the clock for analysis output; animation code may use `requestAnimationFrame`/`performance.now` only inside `src/ui` animation helpers: if the static-safety test bans these, extend its allow-list narrowly and say so).

Keep the keyboard-map section accurate (the old text says "no shortcuts in Phase 4").
