# Phase 5 Plan 04: Gated polish: system-aware light and dark themes, and J/K suspect stepping

## Phase Goal

ROADMAP Phase 5 goal (verbatim): "Verify the complete vertical slice on the documented rebuild path, fix trust/accessibility/performance gaps, and only then add optional visual polish behind a green-check gate."

This plan implements the two gated success criteria: "Gate: only if all committed checks above pass, system-aware dark/light themes may be added without contrast regressions or network dependencies" (POLISH-01) and "Gate: only if all committed checks above pass, keyboard shortcuts for suspect stepping and purposeful reduced-motion-aware verdict/timeline/drawer transitions may be added without hiding equivalent controls" (POLISH-02). Roadmap dependency: "If the gate is not green, ship hardening and omit optional polish."

MVP note: the ROADMAP goal line is not a user story; no story is invented here (run `/gsd-mvp-phase 5` if wanted).

Provenance: no CONTEXT.md, RESEARCH.md or SPEC for Phase 5. The governing visual contract is `04-UI-SPEC.md`. Edge truths come from the spec-less probe fallback (7 items, all resolved explicit, listed in must_haves with their category in parentheses).

## What already exists (do not rebuild it)

- POLISH-02 motion: quick task 261020-ftp already shipped the reduced-motion-gated verdict reveal, timeline draw-in and drawer slide (UI-SPEC "Motion Contract"), and quick task 261020-gzd added the landing motion. Plan 05-02 re-verifies them. This plan adds only the stepping fade and the J/K shortcuts, which the UI-SPEC keyboard map lists as "Not shipped (rest of POLISH-02, still open)".
- POLISH-01: every colour is already a custom property on `:root`, and no TypeScript file holds a colour literal (verified by search of src/ui and src/main.ts), so a theme is a token override block plus tests.

<assumption_delta_decision>
Primary noun: the colour token set.
Decision: add-alongside.
Rationale: the base `:root` dark tokens stay the primary set and the default whenever no light preference is expressed; the light theme is one `prefers-color-scheme: light` block that overrides the same token names. Tokens do not become a theme-keyed map, there is no `data-theme` attribute, no toggle and no stored preference.

Primary noun: suspect stepping.
Decision: add-alongside.
Rationale: J and K are supplementary to the visible Previous suspect / Next suspect buttons, live only on the open drawer dialog (so they are active only while that component has focus, the WCAG 2.1.4 exception), and call the same handler; nothing is hidden or replaced.
</assumption_delta_decision>
