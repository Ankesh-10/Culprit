# Phase 5 Plan 03: The three demo cases are rehearsed from a clean start with every caveat visible

## Phase Goal

ROADMAP Phase 5 goal (verbatim): "Verify the complete vertical slice on the documented rebuild path, fix trust/accessibility/performance gaps, and only then add optional visual polish behind a green-check gate."

This plan owns success criterion 3: "The three demo cases are rehearsed from a clean start, with warnings, assumptions, UTC provenance, truncation limits, and low-confidence reasoning remaining visible in the console and Markdown output." It also records the host half of the polish gate (`Host gate: GREEN` or `Host gate: RED`). The Docker half (image build and container probe on Linux) cannot run on this host; it is recorded separately in `05-DOCKER-EVIDENCE.md` from the ci run of the pushed hardening commit or a Docker-host check, and Plan 05-04 requires both halves before any polish.

MVP note: the ROADMAP goal line is not a user story; no story is invented here (run `/gsd-mvp-phase 5` if wanted).

Provenance: no CONTEXT.md, RESEARCH.md or SPEC for Phase 5; choices are planner discretion grounded in the code.

## Findings this plan fixes (verified in the code)

1. `serializeMarkdown` in `src/core/serialization.ts` writes nine fixed sections, and none of them contains the input limits or the truncation flag. The canonical JSON has `limits`, and the console trust footer shows "Limits: 1 MiB of log text, 10,000 events, 100 stack lines per event", but the copied postmortem drops them. Success criterion 3 requires truncation limits in the Markdown too.
2. README "Limitations" still says "the worker and investigation console are still pending", and README "Verification" still describes the suite as covering only serialization and fixture contracts. Both are false since Phase 4.
3. Nothing pins the exact output of the bundled cases as a whole, so an innocent-looking UI or polish change that reaches the core or the export would only be caught if it hit one of the narrower assertions.

Planning-time probe (2026-10-20, throwaway Vitest file, removed): the current Markdown is 70, 79 and 79 newline-terminated lines for checkout, slow-burn and ambiguous; canonical JSON and Markdown hashes are identical for LF and CRLF fixture text; onset classes are spike, ramp and ambiguous.
