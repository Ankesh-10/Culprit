# Phase 2 Plan 01: Strict input contracts and parsers

<objective>
Create the first executable Phase 2 slice: versioned, serializable contracts and strict local parsers for JSON-lines logs, the documented ISO-timestamp plain-text log format, and the existing `culprit-json` history export. Every accepted timestamp becomes explicit UTC, every accepted record gets a stable source identity, and every rejected or ambiguous record becomes a typed, recoverable diagnostic with source line/record information. Preserve the Phase 1 result/serialization shape and repository-relative POSIX path rules.
</objective>

## Dependencies

None. This plan starts from the Phase 1 model, serializer, README boundary, fixtures, and Vitest harness. Plan 02 consumes the normalized log and history contracts produced here; Plan 03 consumes all parser outcomes without adding a second parsing path.

## Must-haves

### Truths

- JSON-lines and the documented ISO-timestamp plain-text log grammar share one normalized `LogEvent` contract and preserve raw/source evidence.
- Empty, malformed, unsupported, and oversized inputs return named typed errors or explicit recoverable diagnostics; nonblank malformed records are never silently discarded.
- Supported multiline stack traces stay attached to their originating event, while orphan, ambiguous, conflicting, and over-limit continuations are visible as line-aware diagnostics.
- History parsing accepts the existing `culprit-json` fixture schema, canonicalizes commit/file/range order, validates required records, and maps `subject` to the required canonical message without inventing arbitrary git-log support.
- Every accepted timestamp is normalized to UTC and every repository path is a validated repository-relative POSIX identity.
- Phase 1 `AnalysisResult`, serializer exports, schema version, and canonical path behavior remain backward-compatible.
