# Phase 2 Plan 03: Pure analyze pipeline and fixture determinism

<objective>
Compose the Phase 2 contracts into one pure `analyze` entry point that returns a serializable normalized analysis stream or a recoverable typed input error. Exercise the same path against all three Phase 1 fixture packages, preserve the Phase 1 canonical JSON/Markdown boundary through an explicit adapter, and prove output stability across repeated runs, permitted record reordering, timezone/locale changes, current-time stubbing, and random-number stubbing.
</objective>

## Dependencies

Requires Plans 01 and 02. Plan 01 supplies parsing, typed errors, UTC/path normalization, and history contracts; Plan 02 supplies grouping, buckets, and onset. This plan deliberately does not implement Phase 3 ranking, worker/UI code, or new input formats.

## Must-haves

### Truths

- One pure `analyze` orchestration path consumes both supported log formats and the documented history export; no fixture or UI path reimplements parsing or onset logic.
- Valid output contains normalized UTC events, stable source IDs, grouped signatures with first-seen/count/source references, canonical commits/ranges, complete fixed UTC buckets, onset evidence, warnings, assumptions, and diagnostics.
- Invalid and oversized input is recoverable through typed outcomes with line/record diagnostics; it never becomes a misleading blank success or an uncaught generic exception.
- Phase 1 canonical JSON/Markdown remains valid and deterministic while Phase 2 supplies its parsed stream; no Phase 3 ranking claim is fabricated.
- The same canonical output is produced across repeated calls, permitted input ordering, host timezone/locale, current-time/random stubs, and the three checked-in fixtures.

### Artifacts this phase produces

- `src/core/model.ts`: `AnalysisStream`, `AnalysisOutcome`, and the complete Phase 2 stream fields while preserving Phase 1 contracts.
- `src/core/pipeline.ts`: `analyze(input)` and `toAnalysisResult(stream)`.
- `tests/core/pipeline.test.ts`: end-to-end parser/group/bucket/onset and typed-error contract tests.
- `tests/core/determinism.test.ts`: order, timezone, locale, current-time, randomness, and byte-stability tests.
- `tests/core/analysis-fixture.test.ts`: checkout, slow-burn, and ambiguous fixture pipeline contracts.
- `src/core/serialization.ts`: only the minimal adapter changes required to serialize the Phase 2 result without changing Phase 1 field meanings.

### Key links

- `src/core/pipeline.ts` → `src/core/log-parser.ts` and `src/core/history-parser.ts` via the single parser dispatch path.
- `src/core/pipeline.ts` → `src/core/signatures.ts`, `src/core/buckets.ts`, and `src/core/onset.ts` via pure composition order.
- `src/core/pipeline.ts` → `src/core/serialization.ts` via `toAnalysisResult` and canonical output.
- `tests/core/analysis-fixture.test.ts` → `fixtures/incidents/*` via repository-relative shared inputs, not duplicated constants.
- `tests/core/determinism.test.ts` → `src/core/normalization.ts` and `src/core/pipeline.ts` via stable IDs and environment-independent output.
