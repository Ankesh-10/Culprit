# Phase 2 Plan 02: Signatures, fixed UTC buckets, and onset classification

<objective>
Turn normalized log events into deterministic error signatures and a complete fixed-width UTC bucket series. Preserve first-seen time, count, source event IDs, and useful stack evidence, then classify the series using explicit rules into spike, ramp, no-incident (`none` in the Phase 1 wire contract), or insufficient-data outcomes.
</objective>

## Dependencies

Requires Plan 01's `LogEvent`, UTC normalization, stable source IDs, stack-frame ownership flags, and input limits. Plan 03 composes these pure functions into the end-to-end `analyze` pipeline.

## Must-haves

### Truths

- Normalization strips only documented variable values and preserves exception/operation identity, representative raw evidence, first-seen UTC, count, stable event references, and meaningful application frames.
- Buckets are fixed-width UTC half-open intervals, include gaps as zeroes, use deterministic boundary handling, and never anchor to current time.
- Onset classification uses published constants and returns spike, ramp, no-incident (`none` on the existing wire contract), or insufficient-data with the evidence used for the decision.
- Signature and bucket arrays have explicit ordering rules, so input ordering and host locale cannot change the result.
- Vendor-only or ambiguous stack evidence remains visible as a diagnostic rather than becoming fabricated application evidence.
