# Phase 4 Plan 02: Honest page states and the case-file visual system

## Phase Goal

ROADMAP Phase 4 goal (verbatim): "Make the analysis useful in the browser through one-click case studies, an evidence-first verdict, linked timeline investigation, and recoverable accessible states."

## Planning decisions honored

Decision IDs come from the register in Plan 04-01: D-01 (plain DOM and CSS), D-05 (text-only DOM), D-06 (state machine, latest request wins, 150 ms banner, 60% previous result), D-07 (tokens, type scale, hero and gradient removed), D-08 (local fonts with system fallback), D-09 (no transitions; the loader icon rotates only under `prefers-reduced-motion: no-preference`).

Edge-coverage source: spec-less fallback; edge predicates come from the UI-SPEC "UI Considerations" table and the ROADMAP Phase 4 success criteria.

Revision note (checker revision 1): this plan carries the states and visual-system half of the former Plan 04-01. The font registration call lives in `mountApp`, so `src/main.ts` is not edited again.

Scope note (13 files, above the 10-file guideline, justified): three files are tests, `src/assets/fonts/FONTS.md` is a short provenance note, and `index.html` only gains the icon sprite and header chips. The state machine (Task 1, 6 files) and the visual system (Task 2, 9 files) are coupled through `src/ui/app.ts` and `src/styles.css`, and every plan after this one builds on both. Revision 2 added `tests/ui/contrast.test.ts` and moved the font-licence assertion from `tests/ui/static-safety.test.ts` into `tests/ui/case-picker.test.ts`, so the plan stays at 13 files and Task 2 stays at 9.

<objective>
Make every page state honest and legible (UX-08): an icon plus text for each state, the 150 ms loading rule, latest-request-wins, live announcements and focus to the result heading. Then give the console its case-file look (UX-09, UX-01): real-data case cards with sparklines, a collapsing case switcher, the token stylesheet with visible focus, and local Geist fonts with the system stacks as the recorded fallback.

Purpose: a judge can always tell what the console is doing and what it found, with or without colour vision, at laptop and phone widths.
Output: page state machine, status and panel renderers, case picker with sparklines, font loader, the rewritten stylesheet, and two test suites plus a static-check extension.
</objective>
