# Phase 4 Plan 01: One-click case analysis through the worker boundary

## Phase Goal

ROADMAP Phase 4 goal (verbatim): "Make the analysis useful in the browser through one-click case studies, an evidence-first verdict, linked timeline investigation, and recoverable accessible states."

MVP note: the ROADMAP goal line is not written as a user story ("As a / I want to / so that"). No story is invented here; run `/gsd-mvp-phase 4` if a story frame is wanted.

## Phase decision register

No CONTEXT.md exists for this phase. Locked inputs are the approved `04-UI-SPEC.md`, the ROADMAP Phase 4 success criteria, and `.claude/CLAUDE.md`. The planner assigns these IDs once here; every Phase 4 plan cites them.

- D-01 (CLAUDE.md, UI-SPEC Design System): plain DOM modules, semantic HTML, native CSS, hand-authored SVG; no framework, chart library, CSS framework, CDN, or new npm dependency.
- D-02 (UI-SPEC Data contract): the UI keeps the full `AnalysisStream`. `toAnalysisResult(stream)` feeds the verdict, shortlist, confidence and Markdown; the stream itself feeds log lines, changed files and bucket signature counts.
- D-03 (UI-SPEC module table): analysis runs in `src/worker/analyze.worker.ts` with a main-thread fallback when `Worker` construction fails.
- D-04 (UI-SPEC Data contract): bundled incidents load through Vite `?raw` imports of `fixtures/incidents/{id}/logs.jsonl` and `history.json`, with names, purposes and onset class from `manifest.json`. No network request of any kind.
- D-05 (UI-SPEC untrusted-data rule): every data-derived string reaches the DOM through `textContent` or `setAttribute`; a static test fails on any HTML-string sink in `src/`.
- D-06 (UI-SPEC Interaction and State Contract): page state machine `idle -> loading -> done | error`, latest request wins, 150 ms loading-banner delay, previous result dimmed to 60% with `aria-busy` (Plan 04-02).
- D-07 (UI-SPEC Color, Typography, Spacing): dark theme only; every value is a custom property; four type sizes and two weights; the shipped hero h1, eyebrow labels and radial gradient are removed (Plan 04-02).
- D-08 (UI-SPEC Font row): Geist and Geist Mono load only from local WOFF2 files under `src/assets/fonts/` with the OFL licence; no Geist file exists on this machine, so the system stacks are the shipped fallback (Plan 04-02); the optional font-supply step sits in the final checkpoint (Plan 04-08).
- D-09 (POLISH-01/02 out of scope): no light theme, no keyboard shortcuts, no transitions.

Plans 04-03 to 04-08 add D-10 to D-17 for their own regions.

Edge-coverage source: no SPEC.md exists for this phase (spec-less fallback). Edge predicates in `must_haves` come from the UI-SPEC "UI Considerations" table and the ROADMAP Phase 4 success criteria; no separate edge-coverage section is invented.
