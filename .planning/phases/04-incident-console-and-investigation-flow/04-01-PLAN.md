# Phase 4 Plan 01: One-click case analysis, worker boundary, and honest page states

## Phase Goal

ROADMAP Phase 4 goal (verbatim): "Make the analysis useful in the browser through one-click case studies, an evidence-first verdict, linked timeline investigation, and recoverable accessible states."

MVP note: the ROADMAP goal line is not written as a user story ("As a / I want to / so that"). No story is invented here; run `/gsd-mvp-phase 4` if a story frame is wanted.

## Planning decisions honored

No CONTEXT.md exists for this phase. Locked inputs are the approved `04-UI-SPEC.md`, the ROADMAP Phase 4 success criteria, and `.claude/CLAUDE.md`. Decision IDs below are planner-assigned so later plans and the checker can trace them.

- D-01 (CLAUDE.md, UI-SPEC Design System): plain DOM modules, semantic HTML, native CSS, hand-authored SVG; no framework, chart library, CSS framework, CDN, or new npm dependency.
- D-02 (UI-SPEC Data contract): the UI keeps the full `AnalysisStream`. `toAnalysisResult(stream)` feeds the verdict, shortlist, confidence and Markdown; the stream itself feeds log lines, changed files and bucket signature counts.
- D-03 (UI-SPEC module table): analysis runs in `src/worker/analyze.worker.ts` with a main-thread fallback when `Worker` construction fails.
- D-04 (UI-SPEC Data contract): bundled incidents load through Vite `?raw` imports of `fixtures/incidents/{id}/logs.jsonl` and `history.json`, with names, purposes and onset class from `manifest.json`. No network request of any kind.
- D-05 (UI-SPEC untrusted-data rule): every data-derived string reaches the DOM through `textContent` or `setAttribute`; a static test fails on any HTML-string sink in `src/`.
- D-06 (UI-SPEC Interaction and State Contract): page state machine `idle -> loading -> done | error`, latest request wins, 150 ms loading-banner delay, previous result dimmed to 60% with `aria-busy`.
- D-07 (UI-SPEC Color, Typography, Spacing): dark theme only; every value is a `--color-*`, `--viz-*`, `--space-*` or `--font-*` custom property; four type sizes (48/24/16/14) and two weights (400/600); the shipped hero h1, eyebrow labels and radial gradient are removed.
- D-08 (UI-SPEC Font row, orchestrator note): Geist Variable and Geist Mono Variable are loaded only from local WOFF2 files under `src/assets/fonts/` with the OFL licence beside them. No Geist file exists on this machine today, so the system stacks are the shipped fallback (clearly recorded in `src/assets/fonts/FONTS.md`); the optional font-supply step sits in the final checkpoint of Plan 04-05 and blocks nothing.
- D-09 (POLISH-01/02 out of scope): no light theme, no keyboard shortcuts, no transitions. The only motion is the loader icon rotation under `prefers-reduced-motion: no-preference`.

Edge-coverage source: no SPEC.md exists for this phase (spec-less fallback). Edge predicates in `must_haves` come from the UI-SPEC "UI Considerations" table and the ROADMAP Phase 4 success criteria; no separate edge-coverage section is invented.

5. `src/ui/analysis-client.ts`: export `interface AnalysisClient { analyze(input: AnalysisInput): Promise<AnalyzeResponse>; dispose(): void }` and `createAnalysisClient(options?: { createWorker?: () => WorkerLike | null })`, where `WorkerLike` is the subset `postMessage`, `addEventListener('message' | 'error')`, `terminate`. The default factory is exactly `new Worker(new URL('../worker/analyze.worker.ts', import.meta.url), { type: 'module' })` written inline (Vite only detects that literal pattern) inside try/catch returning null. The worker is created lazily on the first `analyze` call. Requests get increasing integer ids; pending promises are keyed by id in a `Map`. A `message` event resolves the matching pending promise (unknown ids are ignored). If the factory returns null or throws, or the worker emits `error` or `messageerror`, the client terminates it, marks itself main-thread-only, and answers every pending and future request with `handleAnalyzeRequest` scheduled through `setTimeout(..., 0)` so a loading state can paint first. `dispose()` terminates the worker.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supplied log/history strings to the DOM | Commit subjects, authors, messages, signatures, paths and diagnostics are untrusted text rendered into the page |
| Main thread to worker | Structured-clone messages carry the full analysis input and stream |
| Browser page to network | The privacy promise is that no log or history byte ever leaves the tab |
