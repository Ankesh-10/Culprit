# Phase 4 Plan 05: Bring your own log and history, recoverable validation errors, and the end-of-phase walk-through

## Phase Goal

ROADMAP Phase 4 goal (verbatim): "Make the analysis useful in the browser through one-click case studies, an evidence-first verdict, linked timeline investigation, and recoverable accessible states."

## Planning decisions honored

Decision IDs are the planner-assigned IDs from Plan 04-01.

- D-05: file names and pasted text reach the DOM only as text; file names also flow into provenance and the Markdown, where Phase 3 escaping applies.
- D-06: own-input analysis uses the same state machine and worker client as bundled cases (latest request wins, 150 ms banner).
- D-08: the optional Geist font supply happens only in this plan's final checkpoint and blocks no implementation task; without it the documented system stacks ship.
- D-16 (UI-SPEC Input panel and Data contract): files over 1 MiB are rejected before reading; log formats are JSON-lines and plain text with auto-detect; history is fixed to the Culprit JSON export because the Phase 2 parser does not support `git-log`.
- D-17 (UI-SPEC Copywriting): error actions use the mapped copy per diagnostic code; Clear inputs is the only destructive action, with a two-step inline confirmation.

Planner discretion: MALFORMED_RECORD without a line number reads "Record {r} of the {noun} couldn't be read. Fix or remove that record, then analyze again." or, with neither line nor record, "The {noun} couldn't be read. Fix the file, then analyze again."; the error summary shows at most 20 entries followed by "{n} more diagnostics are not shown."; pasted inputs use the source names `pasted-log` and `pasted-history`; when a chosen log and history share a file name the history source becomes `history/{name}` so diagnostics map to the right field; file sizes below 1 MiB display in B or KiB.

Human-verification mode: the project runs `workflow.human_verify_mode: end-of-phase`, and the orchestrator asked for one human checkpoint at the end of the final plan. Task 3 is that single checkpoint; it consolidates every `<human-check>` from Plans 04-01 to 04-04 so the user reviews the phase once.

Edge-coverage source: spec-less fallback; edge predicates come from the UI-SPEC "UI Considerations" table and the ROADMAP Phase 4 success criteria.

<objective>
Let a developer analyze their own incident (ROADMAP Phase 4 criterion 1: "or provide supported file/text inputs") through file pick, drag-and-drop or paste, with a pre-read size gate and plain-language, recoverable validation errors that point to the field to fix (UX-08), fully keyboard-operable (UX-09), alongside the one-click cases (UX-01). Then confirm the whole console in one human walk-through at laptop and phone widths.

Purpose: turns the demo into a usable tool while keeping every failure honest and recoverable.
Output: `src/ui/intake.ts`, `src/ui/inputs.ts`, error-summary mapping, README console notes, and the final human checkpoint.
</objective>

- A diagnostic's `source` is the source name passed to `analyze()` for that input (`input.logs.source` / `input.history.source` after `normalizeRepositoryPath`), or `analysis` for option errors. - `normalizeRepositoryPath(value)` (src/core/normalization.ts) throws for empty, absolute, drive-letter and `..`-segment paths; `analyze()` turns a bad source into `INVALID_ANALYSIS_INPUT`, so the UI must pass a safe name.

- Empty log text yields `EMPTY_INPUT` from the log source; history text `{` yields `MALFORMED_RECORD` ("History export is not valid JSON.") with line and record null.
- `DEFAULT_LOG_LIMITS.maxLogBytes` is 1,048,576.
