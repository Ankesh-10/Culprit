# Phase 4 Plan 07: Markdown postmortem copy and the trust footer

## Phase Goal

ROADMAP Phase 4 goal (verbatim): "Make the analysis useful in the browser through one-click case studies, an evidence-first verdict, linked timeline investigation, and recoverable accessible states."

## Planning decisions honored

Decision IDs come from the register in Plan 04-01 plus D-15 added here.

- D-02: Markdown, warnings, assumptions and limits come from `toAnalysisResult(stream)` and the stream.
- D-05: footer, status line and fallback box receive data only through `textContent`, `setAttribute` and the textarea `value` property.
- D-10: the copied Markdown keeps full score precision.
- D-15 (UI-SPEC Copy flow): source is `serializeMarkdown(toAnalysisResult(stream))` computed on demand; primary path `navigator.clipboard.writeText`; any failure reveals the selected fallback box; no auto-dismiss timer; the button label never changes; the legacy copy command is never used silently.

Planner discretion: the copy control also sits under the state panel for no-suspect results; `formatInteger` is added to format.ts for the limits line ('10,000 events') without any locale API.

Edge-coverage source: spec-less fallback; edge predicates come from the UI-SPEC "UI Considerations" table and the ROADMAP Phase 4 success criteria.

Revision note (checker revision 1): this is the former Plan 04-04 Task 3, split out into its own plan and divided into a copy tracer plus a footer task.

<objective>
Let the reader take the result away as a deterministic Markdown postmortem with visible success or fallback feedback (UX-07), and keep every warning, diagnostic, assumption and the UTC note visible beside the result (UX-08), keyboard-operable at both widths (UX-09).

Purpose: a shareable, honest write-up whose caveats travel with it.
Output: `src/ui/copy.ts`, the copy-feedback reducer, `src/ui/trust-footer.ts`, the footer view, `formatInteger`, and tests.
</objective>
