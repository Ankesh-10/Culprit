### Identity and idea

Direction: a quiet **case file**, not a generic dark dashboard. The idea comes from the subject: a commit is a suspect, the onset is the time of the incident, the shortlist is a lineup, and the diamond that marks a commit on the timeline is the product's one recurring motif.

- **One motif, used consistently.** The 16px diamond (the timeline's commit mark) is also the wordmark glyph in the header (filled, ink), the rank marker on shortlist cards (`#1` filled aqua `#199e70`, `#2`/`#3` filled gray `#8fa0b8`, matching the chart exactly), and the check glyph on the loaded case card (ink). No other decorative shape exists.
- **The shortlist is a lineup.** Section heading "Suspect lineup" (sentence case, Body 500). Cards sit side by side at 1024px and up with equal height and the rank diamond leading each card. Copy remains evidence-first; the word "suspect" never implies guilt (see Copywriting voice rules).
- **Case cards show real data, not icons.** Each case card carries a 28px-high error-rate sparkline of that fixture's buckets (2px line `#3987e5`, no axes, no fill), computed by running the pure `analyze()` core once per bundled case on idle after first paint (deterministic, local, no network). If it fails or is slow, the card renders without the sparkline; the sparkline is `aria-hidden` and its meaning is already in the chip text ("Sharp spike", "Slow ramp", "Ambiguous").
- **No ornaments.** A four-step surface ladder carries elevation: page `#07080a`, surface `#0d0d0d`, elevated `#101111`, raised `#121212`. Every card is edged by a 1px `#242728` hairline. There are no shadows, gradients, glass, emoji, eyebrow labels, uppercase tracked captions, icon-topped cards, or index numbering other than real rank. Chrome is monochrome: white marks the one primary action, ink marks selection, and `#57c1ff` marks keyboard focus only. Status accents appear only in icons, status stripes and soft badges; data-viz colours appear only in chart marks. The remaining lines carry function: control and drop-zone borders (non-text contrast; the drop zone is 2px dashed), table row rules, and chart baseline/gridlines (a measured instrument). The leading-suspect aqua (`#199e70`) never shares an element with a focus ring. The one signature moment is the flat three-stripe red band behind the header text, plus a barely visible dot grid behind the page (see "Decorative layers" under Color); both are flat fills, aria-hidden, and never carry meaning.
- **Motion is purposeful and gated.** Scroll-driven motion, GSAP and stock imagery still do not apply: Culprit is an offline analysis tool with no network assets. Purposeful, reduced-motion-aware motion (a staggered entrance, a verdict reveal, a timeline draw-in, a drawer slide) is specified in the Motion Contract below; it implements part of POLISH-02 early, at the user's request.

| `src/ui/state.ts` | Page state machine and reducer (`idle`, `loading`, `error`, `done`) plus copy-feedback state | Vitest, pure |

Untrusted-data rule (hard): every string originating from logs, history, file names or paste (messages, subjects, authors, paths, signatures, diagnostics) is inserted with `textContent` / `createTextNode` / `setAttribute`. `innerHTML`, `insertAdjacentHTML` and template-string HTML are forbidden for any dynamic value. A test greps `src/ui` for `innerHTML` and fails on any hit.

### Data contract the UI renders

The UI calls `analyze(input)` (worker) and receives `AnalysisOutcome`.

- `ok: false` -> error state (diagnostics are `InputDiagnostic[]`: `source`, `code`, `message`, `line`, `record`).
- `ok: true` -> keep the `AnalysisStream`. Use `toAnalysisResult(stream)` for the verdict, shortlist, confidence, warnings, assumptions and for `serializeMarkdown(result)`. Use the stream directly for what the result projection drops: `normalizedEvents` (log lines), `commits` (changed files and line ranges), and `buckets[].signatureCounts` / `eventIds` (signature filtering and bucket log lines).
- The history export contains changed **line ranges and +/- counts, not diff text**. The drawer's "diff/line evidence" is files, ranges, counts and matched stack frames. The UI must never fabricate hunks and must say so in the drawer (copy below).
- Score is 0..1 (frozen weights 0.35 / 0.30 / 0.25 / 0.10). Display: cards 2 decimals, drawer math 3 decimals, always followed or preceded by "rounded for display"; the copied Markdown keeps full precision.
- Bundled incidents load via Vite `?raw` imports of `fixtures/incidents/{id}/logs.jsonl` and `history.json`, with names, purposes and onset class from `manifest.json`. No `fetch`.
- Input limits to surface in the UI: 1 MiB of log text, 10,000 events, 100 stack lines per event (`DEFAULT_LOG_LIMITS`). Files larger than 1 MiB are rejected before reading into memory.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, chip inner vertical padding, marker label offset |
| sm | 8px | Compact element spacing, chip horizontal padding, table cell vertical padding, gap between buttons |
| md | 16px | Default element spacing, card padding on phone, table cell horizontal padding, form field gaps |
| lg | 24px | Card padding at 640px and up, gap between major regions |
| xl | 32px | Gap between the verdict block and the next region on laptop, drawer padding |
| 2xl | 48px | Bottom-of-page breathing room |
| 3xl | 64px | Top-of-page header offset on laptop, empty-state vertical padding |

Container: `max-width: 1152px`, horizontal padding 16px below 640px and 24px from 640px up, centered.

Exceptions (all explicit):

- Controls draw **36px** high and keep a **44px hit area** through a transparent 4px band above and below (a centred `::after`, so the core-path 44px minimum holds): buttons, case cards, case-switcher toggles, table action buttons and the drawer buttons. Icon-only buttons stay 44px wide (drawer close, drawer navigation). The log format `<select>` stays 44px tall: it is a single-line field (Raycast's store-search-bar height) and a select cannot carry the band. Commit markers keep a 44px hit area on coarse pointers and 24px on fine pointers.
- 1px hairlines (control borders, grid lines, axes, table rules) and 2px strokes (series line, drop-zone border, drag-over border, focus ring width and its 2px offset, surface ring and gap around markers and segments) are stroke widths and focus geometry, not spacing.
- SVG mark sizes are mark specs, not spacing: markers 8, 12 and 16px; sparkline height 28px; plot heights listed in the timeline section.
- Drawer width 480px (a multiple of 4) on laptop; full viewport width on phone.

Radii: card 10px (panels, case cards, banners, lineup cards, tables, trust footer, confirm row), control 8px (buttons, inputs, drop zone, select, skip link), row 6px (caution banner, readout bar, tooltip, timeline slider), key 4px (chips, badges, `kbd`). The drawer is 0 and the commit-marker hit circle is 50%.

## Typography

Exactly four sizes and two weights (Display hash 500, Heading 500, Label strong 500, button text 500).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Display | 48px at all widths (7 mono characters is about 202px, inside the 288px content width at 320px) | 500 | 1.1 | Leading-suspect short hash in the verdict card only (Geist Mono). Exactly one per view. Proportional figures, no `tabular-nums`. This is the page's one very large element; everything else steps down to 24px or less. |
| Heading | 24px | 500 | 1.2 | Wordmark "Culprit", verdict commit subject, shortlist rank label ("#1"), state headings (empty, error, no-incident), drawer title, and the result `h2` ("Result: {case or file name}") |
| Body | 16px | 400 | 1.5 | Prose, interpretation sentence, rationale, evidence details, textarea and input text (16px prevents iOS zoom), button text at weight 500 |
| Label | 14px | 400 / 500 | 1.4 | Table cells and headers (500), chips, key-value labels (400) and values (500), axis tick labels, legend, tooltip, readout bar, log-line rows, helper text |

Weights: **400 regular** and **500 medium** only. No 600, 700, or italics for emphasis; `b`, `strong` and `th` are set to 500 so the user-agent bold never appears. Features: body enables `font-feature-settings: "calt", "kern", "liga", "ss03"`. Mono selectors (hashes, paths, signatures, log lines, textareas, `kbd`) reset `font-feature-settings` to `normal` and ligatures to `none`, so untrusted text renders exactly as written.

Rules:

- Section headings (`h2`) in cards use **Body 16px / 500, sentence case, no letter-spacing, no uppercase**, with the real heading semantics intact; the visual size does not change the heading level. There are no eyebrow labels anywhere.
- `font-variant-numeric: tabular-nums` only in table number columns, axis ticks and the readout bar; never on Display or Heading.
- Mono (`Geist Mono`) is used for short hashes, file paths, line ranges, signatures and log lines, at the same size and weight as the surrounding role. Long mono strings wrap with `overflow-wrap: anywhere`; never ellipsis-truncate a hash, path or signature without a full-text equivalent in the drawer or log panel.
- Commit subjects and messages wrap (`overflow-wrap: anywhere`) up to 3 lines in cards (`line-clamp: 3` with the full text in the drawer) and unlimited in the drawer.
- Replaces the current `clamp(3rem, 10vw, 6rem)` hero h1. The shipped hero treatment is removed in Phase 4.

## Data Visualization Contract

`dataviz` guidance applied here: form choice, color job assignment, palette validation, mark specs, hover layer, accessibility pass. Adapted to hand-authored SVG plus native CSS (no chart library).

### Form (dataviz step 1)

One shared-time-axis SVG, three stacked lanes in one `<svg>` so a single x-scale governs all of them:

| Lane | Job | Form | Height (laptop / phone) |
|------|-----|------|-------------------------|
| Errors | Trend over time, single series | Line plus 10% area wash on bucket centers; **emphasis** form when a signature filter is on (total in gray context, selected signature in blue) | 160px / 128px plot |
| Onset | Mark a time window | Band spanning `onset.windowStartUtc`..`windowEndUtc` across the Errors lane with a 2px top bracket and the label "Onset window" | overlay |
| Commits | Place discrete events on the same x | Diamond markers on a 48px lane below the plot | 48px |
| Axis | UTC ticks | 3 ticks on phone, up to 6 on laptop, labels `HH:MM` plus the date once at left, suffix "UTC" on the axis title | 32px |

No dual axis, no second y-scale, no pie, no per-signature rainbow. Selected-signature filtering never adds colors.

### Color (dataviz steps 2-3)

- Categorical jobs: three entities only (errors, onset window, leading suspect), assigned slots 1, 2, 3 in fixed order, never cycled. With three slots the all-pairs gate applies and passes (record below).
- Series count ladder: 1 series on the plot (errors), so no categorical legend is *required* for the line, but the legend row is always shown because the chart carries 4 mark types; legend entries are mark-shaped (line key, band swatch, diamond, hollow diamond).
- Error rate here is a count series, not a good/bad status, so it wears a categorical hue, not status tokens (dataviz collision rule).
- Text never wears series color: direct labels use ink / ink-2; identity comes from the adjacent mark.
- Onset band alone must not carry meaning by hue: it also has the 2px top bracket, the direct label, and appears as a row flag in the table twin.

### Interaction (dataviz step 5, adapted for keyboard and touch)

Tooltips enhance and never gate: every tooltip value is also in the always-visible readout bar and the table twin.

- Crosshair snaps to the nearest bucket center. Fine pointer: hover moves the crosshair and shows a tooltip (`#121212`, 1px `#242728` hairline, 6px radius) listing `HH:MM–HH:MM UTC`, error count (value strong 500, label secondary), signature count, "Inside onset window" when true, and commit short hashes in the bucket. Coarse pointer: tap selects the bucket, no tooltip; the readout bar carries the same text.
- Hit targets exceed marks: one transparent overlay rect picks the nearest bucket by x (no per-bucket DOM nodes, so 10,000 buckets are cheap); commit marker hit areas are 24px (fine) / 44px (coarse), including the 2px ring.
- **Readout bar** (always visible, directly under the chart, not hover-dependent, `aria-live="polite"` with `aria-atomic="true"`): `04:30–04:35 UTC · 42 errors · 3 signatures · Inside onset window · Commits 3a4b5c6` plus the button "Show log lines (42)". Default selection on load is the **onset bucket** (or the peak bucket when there is no onset), so the bar is never empty.
- Filters sit in one row above the chart inside the timeline card header: signature filter chip with "Clear filter" and the toolbar buttons "Jump to onset", "Jump to peak". The chart, readout bar, log panel and table twin all re-render against the same filter slice.
- Refetch keeps the frame: when the user switches case while a result is displayed, the previous region stays at 60% opacity with `aria-busy="true"` until the new result replaces it (no skeleton, no layout jump).
- The y-axis max is computed from the *unfiltered* totals so applying a signature filter never rescales the axis.

### Accessibility pass (dataviz step 6)

- Legend always present (mark-shaped keys), direct labels limited to onset, #1, peak.
- **Table twin**: `<details><summary>Timeline data table</summary>` under the chart with one row per bucket (capped at 100 rows rendered, "Show next 100" button): Interval (UTC), Errors, Signatures, Onset window (text "Yes"/"—"), Commits (short hashes), and a per-row button "Show log lines". This is the non-hover, non-pointer equivalent for every value on the chart.
- **Keyboard**: the chart plot is one tab stop with `role="slider"`, `aria-orientation="horizontal"`, `aria-label="Error timeline, use left and right arrow keys to move between 5-minute intervals"`, `aria-valuemin="0"`, `aria-valuemax="{n-1}"`, `aria-valuenow`, and `aria-valuetext` equal to the readout text. Keys: Left/Right = previous/next bucket, PageUp/PageDown = 12 buckets, Home/End = first/last, Enter or Space = open the log lines for the selected bucket. Top-three commit markers are `role="button"` stops (Tab) that open that suspect's drawer. Focus ring on the slider is drawn as the 2px `#57c1ff` focus ring around the plot rectangle plus the selected-bucket crosshair.
- Color is never the only signal: onset = bracket + label + table flag; leading suspect = size + label + legend + list rank; filtered series = legend text "Filtered: {signature}".
- Texture (opt-in): under `@media (forced-colors: active)` and `@media print`, the onset band switches to a 45-degree hatch (`<pattern>`), strokes use `CanvasText` / `Highlight`, markers keep their shapes. Never on by default.
- Text contrast for ink, ink-2 and muted is 7.09:1 or higher on the chart surface. Series, onset, suspect and context marks are 5.00:1 or higher on `#0d0d0d` (3:1 required).

## Motion Contract

Added by quick task 261020-ftp. It implements part of POLISH-02 early (global shortcuts plus purposeful, reduced-motion-aware transitions) at the user's request; the suspect-stepping shortcuts are not shipped and POLISH-02 stays open.

**Tokens** (CSS custom properties on `:root`; the script-side twins in `src/ui/motion-model.ts` are pinned to them by a test):

| Token | Value | Use |
|-------|-------|-----|
| `--motion-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | Every entrance |
| `--motion-enter` | 600ms | Fade and 12px rise of each result section |
| `--motion-stagger` | 80ms per index, capped at index 7 | `--index` delay between sections |
| `--motion-fast` | 150ms | Readout text fade |
| `--motion-draw` | 900ms | Timeline line draw-in |
| `--motion-drawer` | 320ms | Drawer slide |
| decode | 450ms | Verdict hash decode (script) |
| count-up | 600ms | Score and "Matches N of M errors" count-up (script) |

**Entrance choreography.** On a new result the status banner and every result section (verdict, lineup, considered, timeline, log panel, signatures, trust footer) fade and rise 12px over 600ms, staggered 80ms by index. Sections already on screen play at once; sections below the fold play when they first scroll into view (an `IntersectionObserver`, guarded by a `typeof` check). It plays once per result: the stale re-render during a later load never replays it.

**Verdict reveal.** The 7-character hash decodes left to right in about 450ms and ends on the exact hash; the score and the matching-error count count up in about 600ms. The score meter and the confidence segments fill with `transform: scaleX`. The decode and count-up run on an `aria-hidden` overlay span; the real text node is never modified, so assistive technology and tests read the exact value from the first paint, and a finished, cancelled or skipped roll always leaves the exact final text (the overlay is removed). A wrong value is never left visible.

**Timeline.** The primary series line draws in (`stroke-dashoffset`), the onset band wipes in from its left edge (`scaleX`), commit diamonds pop in staggered (`scale`, 40ms apart) and the #1 marker emits one pulse ring (plays once, never loops). The draw-in is a class held on the timeline section only while its animations run, so re-selecting an interval, stepping the slider and resizing never replay it. A signature filter crossfades the series (200ms), and the readout text fades in over 150ms on every change.

**Cards, loading and drawer.** Card sparklines sweep in on hover and keyboard focus (the sparkline uses a non-scaling stroke, which makes a dash-offset draw unreliable, so it wipes from the left with `scaleX`). The first-load placeholder gets a thin flat scanline (three sweeps, then still). The drawer slides in over a fading backdrop; closing is instant.

**Command palette.** A native modal `<dialog id="command-palette">` with a search field (`role="combobox"`, `aria-controls`, `aria-activedescendant`), a `role="listbox"` of the three cases plus "Use your own files", a polite result count ("4 results", "1 result", "No matching cases") and a key hint. The active option has `aria-selected` plus a 4px ink left rule, so selection is never colour alone. Opening plays a 160ms rise over the same backdrop fade as the drawer.

**Reduced-motion contract.** Every keyframe, animation and transition lives inside `@media (prefers-reduced-motion: no-preference)`, and the base state (no media query, no script, reduced motion) is already the final state: no running animation, no overlay, exact text, full meters, fully drawn line. Script only starts motion when `prefers-reduced-motion: no-preference` matches, and a script failure never hides content. `tests/ui/contrast.test.ts` enforces this with `motionViolations(css)`: ungated motion, keyframes animating anything but `transform`, `opacity` and `stroke-dashoffset`, `transition: all`, `forwards` or `both` fills, and infinite loops other than the two below all fail. Gradients, glass (`backdrop-filter`) and non-inset shadows still fail their own tests.

**Loops and cancellation.** The only loops are the loading spinner (`culprit-spin`) and the ambient dot-grid drift (`motion-drift`, 48s, linear, one 24px pattern period); the pulse ring and scanline play a finite number of times. Fills are `backwards` only, so finished animations release their elements. No timer or animation blocks input or moves focus; the render pass disposes the previous `MotionScope` (pending frames, observer, listeners) before it rebuilds the body, so latest-request-wins is intact.

**Boundaries.** Animation-frame APIs are allowed only in `src/ui/motion.ts` (a narrow allow-list in `tests/ui/static-safety.test.ts`); `src/core` is untouched, and nothing here reads the clock for analysis output.

## Interaction and State Contract

### Page state machine

```
idle -> loading -> done(completed | low-confidence | no-incident | insufficient-data | no-eligible-commits)
idle -> loading -> error
done|error -> loading   (new load keeps the previous region at 60% opacity, aria-busy)
done|error -> idle      (only via Clear inputs when no result exists)
```

Transitions: choosing a case or pressing "Analyze incident" enters `loading` immediately. The visible loading banner appears only if analysis takes longer than 150ms (avoids a flash); `aria-busy="true"` is set from the first moment. Result and error states replace content in a single render.

### State matrix (UX-08: no state relies on color alone)

| State | Trigger | Banner icon and label | Region content | Focus / announcement |
|-------|---------|----------------------|----------------|----------------------|
| Empty (idle) | First load | info icon, "Ready — no incident loaded" | Input panel with case cards; result region shows the empty-state block | none; skip link targets the heading |

## Copywriting Contract

Voice: calm, precise, evidence-first. Use "suspect", "lead", "worth checking first", "ranked suspicion". Never "culprit found", "caused", "root cause", "broke production" or probability percentages. Sentence case; no exclamation marks.

| Element | Copy |
|---------|------|
| Primary CTA (own inputs) | Analyze incident |
| Case card buttons | Names from manifests: "Checkout outage", "Slow-burn inventory failure", "Ambiguous search regression"; each card's accessible name: "Load {name}" |
| Own files toggle | Use your own files |
| Verdict action | Inspect evidence |
| Copy action | Copy Markdown postmortem |
| Page title (document) | Culprit — Incident analysis (unchanged) |
| Header purpose line | Find the commits worth checking first, with evidence you can verify. |
| Privacy chip | Local only: nothing leaves this browser |
| UTC chip | All times UTC |
| Empty state heading | Load an incident to see which commits to check first |
| Empty state body | Choose a bundled case to see Culprit work in seconds, or add your own log and git history. Everything stays in this browser. |
| Loading | Analyzing locally... |
| Error heading | We couldn't analyze these inputs |
| Error body (generic) | Nothing was uploaded and nothing changed. Fix the item below and analyze again, or load a bundled incident to compare formats. |
| Error action: EMPTY_INPUT | The {log / git history} is empty. Choose a file or paste text, then analyze again. |
| Error action: MALFORMED_RECORD | Line {n} of the {log / git history} couldn't be read. Fix or remove that line, then analyze again. |
| Error action: UNSUPPORTED_FORMAT | This format isn't supported. Use a JSON-lines log or plain text with ISO timestamps and levels, plus a Culprit JSON history export. The README lists the supported formats. |
| Error action: INPUT_LIMIT | This input is over the limit of 1 MiB or 10,000 events. Trim the log to the incident window and try again. |
| Error action: other codes | Show the parser diagnostic message verbatim (as text) with its line number. Prefix: "Check {log / git history}:" |
| File too large (pre-read) | {file name} is {x.x} MiB. The limit is 1 MiB. Trim the file to the incident window and choose it again. |
| No-incident heading | No incident detected |
| No-incident body | The log shows no sustained rise in errors, so there is no onset to trace back from. Culprit doesn't rank commits without one. Check that your log covers the failure window. |
| Insufficient-data heading and body | Not enough data to find an onset. / The log has too few errors or too short a time span. Add more of the log from before and during the failure. |
| No eligible commits heading and body | No commits before the onset. / Every supplied commit landed after the onset window started, so none can be ranked as a suspect. Add earlier history to compare. |
| Low-confidence lead sentence | Low confidence. Treat these as leads to check, not a diagnosis. |
| Label chips | Low confidence · Ambiguous · Weak evidence · No clear culprit |
| No-clear-culprit headline | No clear culprit |
| Verdict standing caveat | Ranked suspicion from log timing and stack evidence. Verify the diff before acting. |
| Score helper | Suspicion score from 0 to 1. This is ranked suspicion, not probability. |
| Drawer diff note | Culprit's history export lists changed line ranges, not diff text. Open the commit in your repository to read the diff. |
| Drawer caveat | This score ranks suspicion from timing, stack, novelty and change size. It is not proof that this commit caused the incident. |
| Copy success | Markdown postmortem copied (N lines). |
| Copy fallback | Couldn't copy automatically. The Markdown is selected below. Press Ctrl+C (Cmd+C on Mac). |
| Log panel empty bucket | No log lines in this interval. Pick a highlighted interval or use "Jump to peak". |
| Signature filter chip | Filtered: {signature} · Clear filter |
| Timeline key hint | Keys: ← → move between intervals, Enter opens log lines (keys drawn as `kbd` keycaps) |
| Destructive confirmation | Clear inputs: Remove the loaded log and git history from this page? The current result stays until you load something new. Buttons: "Clear inputs" and "Keep inputs", both secondary chrome inside the critical-striped confirm row (no status fill on buttons). |

Heading and label case: sentence case throughout, typed and rendered as written. No uppercase transforms, no tracked small-caps labels, no eyebrows.

Region headings: "Load an incident", "Most likely suspect", "Suspect lineup", "Timeline", "Log lines", "Error signatures", "Warnings and caveats".

Destructive actions in this phase: only "Clear inputs" (discards pasted or loaded text). Approval is an inline two-step confirmation (the button swaps to the confirm row; no timeout; Escape cancels; focus lands on "Keep inputs"). No other destructive action exists; copy is non-destructive.
