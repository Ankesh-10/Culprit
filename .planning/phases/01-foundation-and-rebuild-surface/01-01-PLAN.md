# Phase 1 Plan 01: Tracer-first contracts and one incident

## Goal

Create the smallest complete, runnable path from a repository-relative incident fixture to a typed deterministic result and Markdown serialization, with a Vite page proving the project starts. Later analysis phases must extend these contracts rather than invent parallel fixture or output formats.

## Dependencies

None. This is the first implementation wave and establishes the package/toolchain and public core boundary used by Plan 02.

## Must-haves

### Truths

- A clean checkout has a pinned Node 22/npm/Vite/strict-TypeScript/Vitest shell and a non-watch test script.
- One repository-relative checkout fixture is the single source consumed by tests and future quick-load behavior.
- The pure-core result contract includes provenance, limits, warnings, assumptions, diagnostics, evidence, confidence rationale, and stable versions.
- Canonical JSON and Markdown are deterministic, UTC-explicit, path-normalized, and independent of current time, randomness, locale, network, and UI state.
- The built Vite shell starts from `index.html` and does not claim an analysis result before later phases implement analysis.

### Artifacts this phase produces

- `.nvmrc`, `package.json`, `package-lock.json`, `tsconfig.json`, `tsconfig.node.json`, `vite.config.ts`, `index.html`, `src/main.ts`, `src/styles.css`
- `src/core/model.ts`: serializable public contracts and schema/version constants
- `src/core/serialization.ts`: `serializeCanonicalJson(result)` and `serializeMarkdown(result)`
- `fixtures/incidents/checkout-outage/{manifest.json,logs.jsonl,history.json,expected.json}`
- `tests/core/serialization.test.ts` and `tests/core/fixture-contract.test.ts`

## Execution notes

- Plan 02 depends on the contracts and fixture schema in this plan.
- Later phases may extend the result contract only through explicit schema/version changes and must preserve canonical serialization behavior.
