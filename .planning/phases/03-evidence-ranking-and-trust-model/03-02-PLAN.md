# Phase 3 Plan 02: Ranker, confidence labels, and result-contract integration

## Phase Goal

ROADMAP Phase 3 goal (verbatim): "Correlate pre-onset history with error evidence using frozen explainable signals and produce an honest, deterministic top-three interpretation for all bundled incidents."

## Planning decisions honored

- D-01: Onset-window logic in `pipeline.ts` (`interpretSparseRamp` `nonEmpty[1]`, `interpretWeakEvidence` `errorTimes[1]`, `cloneOnset`) is NOT changed; ranking reads `onset.windowStartUtc` as-is.
- D-04: Add the bucket-count guard (`MAX_BUCKETS = 10_000`) so `buildUtcBuckets` cannot throw out of `analyze()`. A history size cap is out of this phase.
- D-05: All new contract fields are required (non-optional); `makeResult` in `tests/core/serialization.test.ts` and `buildTracerResult` in `tests/core/fixture-contract.test.ts` are updated so `tsc --noEmit` passes.

Because D-05 makes `AnalysisResult.ranking` and `ConfidenceRationale.labels` required, `canonicalizeResult` must project them in this plan or typecheck fails; only the canonical JSON projection lands here. Markdown rendering and escaping stay in Plan 03-03.
- D-07: Ordering compares integer micro-units from `toMicro`; separation is computed from micro-unit differences.
