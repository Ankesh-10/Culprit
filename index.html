What it does

Find when the errors started

Culprit buckets error events on a UTC timeline and finds the interval where the rate breaks from its baseline. It labels the shape as a sharp spike, a slow ramp or ambiguous, and says so when it cannot tell. Timestamps with offsets are normalized to UTC first.

Rank the commits worth checking first

Every commit made at or before the start of the onset window gets a fixed-weight score from four signals: proximity 0.35, trace match 0.30, novelty 0.25, churn 0.10. The weights are frozen in the code, so the same input always gives the same order. A score is ranked suspicion, not proof.

See errors and commits on one UTC axis

The error rate, the onset window and the commits share one time axis, with the top suspects marked. Filter by error signature, step through intervals with the arrow keys, or read the same values in the data table, so nothing depends on hover.

Check the arithmetic behind every rank

The drawer shows each signal's value, weight and contribution, the changed files and line ranges, and where they overlap stack frames in the log. The history export lists line ranges, not diff text, so open the commit in your repository to read the diff.

Copy a postmortem you can paste anywhere

One button copies a Markdown summary of the verdict, evidence, confidence and caveats. The same deterministic serializer produces it every time; if the clipboard is unavailable, the text appears selected so you can copy it by hand.

Nothing leaves your browser

Logs and history are read and analyzed on this page; nothing is uploaded and no account is needed. Culprit makes no network requests, so it keeps working without a connection once the page is open, and the same input always produces the same bytes.

  • No network code: tests/ui/static-safety.test.ts fails npm test if the source uses a network or storage API or contains an absolute URL.
  • Byte-identical output: tests/core/determinism.test.ts runs the same analysis repeatedly and compares the bytes.
  • Local analysis: the previews on this page were computed in your browser from the bundled fixtures.

See it work

The checkout outage case, step by step, rendered by the same code as the console.

Step 1 of 5

Paste a log and the git history

Culprit reads JSON-lines or plain-text logs and a Culprit JSON history export. Nothing is uploaded; the text stays in this page.

Step 2 of 5

Find the onset

Errors are counted per interval on a UTC axis, and the onset window marks where the rate breaks from its baseline. Here it is a sharp spike.

Step 3 of 5

Rank the suspects

Every commit made at or before the start of the onset window is scored on proximity, trace match, novelty and churn. The leading suspect carries the diamond; the score is ranked suspicion, not proof.

Step 4 of 5

Read the evidence

The drawer breaks the score into its four contributions and lists the changed line ranges that overlap the failing stack frames.

Step 5 of 5

Hand off a postmortem

Copy the result as Markdown with the verdict, evidence, confidence and caveats, ready for the incident channel.

How it works

  • Inputs: a Culprit JSON history export plus JSON-lines or plain-text logs, up to 1 MiB and 10,000 events.
  • Deterministic UTC output: the same input gives byte-identical results, with every time shown in UTC.
  • Ranked suspicion, not proof: Culprit tells you where to look first; a person still confirms the cause.
